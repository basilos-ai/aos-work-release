# 环境变量

本页逐项解释部署模板中的环境变量。变量名称和默认值以 [`.env.middleware.example`](../.env.middleware.example)、[`.env.studio.example`](../.env.studio.example) 和 [`.env.workbench.example`](../.env.workbench.example) 为准。

## 配置规则

| 文件 | 使用者 | 内容 |
| --- | --- | --- |
| `.env.middleware` | Studio、Workbench、共享中间件 | 网络、中间件镜像和连接信息 |
| `.env.studio` | Studio | Studio 镜像、端口和业务配置 |
| `.env.workbench` | Workbench | Workbench、Runtime 和 Sandbox 配置 |

所有变量必须使用 `变量名=值` 格式：

```shell
JAVA_OPTS=-Xms1g -Xmx2g
```

- 等号两侧不要添加空格。
- `CHANGE_ME_*` 必须替换为实际值。
- 空值表示对应可选能力未启用。
- 密码、Token 和密钥不得提交到 Git。
- 共享中间件连接只维护在 `.env.middleware`。

### PostgreSQL

| 变量 | 模板值 | 填写要求 | 说明 |
| --- | --- | --- | --- |
| `POSTGRESQL_HOST` | `CHANGE_ME_POSTGRESQL_HOST` | 必填 | 容器可访问的 PostgreSQL 地址。本地部署填写 `postgresql`，外部服务填写真实 DNS 或 IP。 |
| `POSTGRESQL_PORT` | `5432` | 必填 | 应用连接 PostgreSQL 的端口，不是宿主机映射端口。 |
| `POSTGRESQL_USERNAME` | `basilos` | 必填 | Studio、Workbench 和 Runtime 共用的数据库账号，初始化时需有创建扩展的权限。 |
| `POSTGRESQL_PASSWORD` | `CHANGE_ME_POSTGRESQL_PASSWORD` | 必填 | PostgreSQL 连接密码；本地部署时也是初始化密码。 |
| `POSTGRESQL_BOOTSTRAP_DATABASE` | `basilos` | 必填 | Studio、Workbench 和 Runtime 共用的数据库。本地 PostgreSQL 首次初始化时创建；使用外部数据库时须预先创建。 |

PostgreSQL 必须支持 `vector` 和 `pg_trgm` 扩展。本地 `postgresql-init` 在应用启动前将两者创建于 `public`，避免 Studio/Workbench 先后启动导致扩展落入不同 schema。外部数据库首次部署前由有权限的账号执行：

```sql
CREATE EXTENSION IF NOT EXISTS vector WITH SCHEMA public;
CREATE EXTENSION IF NOT EXISTS pg_trgm WITH SCHEMA public;
SELECT extname, nspname
FROM pg_extension e JOIN pg_namespace n ON n.oid = e.extnamespace
WHERE extname IN ('vector', 'pg_trgm');
```

`IF NOT EXISTS` 不会移动已有扩展；已有环境若扩展不在 public，应先评估依赖和迁移，不得直接删除或移动。Workbench 启动迁移显式将 `DB_SCHEMA` 放在搜索路径首位、public 放在其后，业务表和迁移记录仍写入 `DB_SCHEMA`。

### 运行与安全

| 变量 | 模板值 | 填写要求 | 说明 |
| --- | --- | --- | --- |
| `JAVA_OPTS` | `-Xms1g -Xmx2g` | 按资源调整 | Studio JVM 初始和最大堆内存。最大值应小于容器或宿主机可用内存。 |

## Compose 内部默认值

`docker-compose.workbench.yaml` 还为 Runtime 调度、工具调用、SMTP、注册邮件队列、日志保留和上传限制提供了默认值。这些值没有放入 `.env.workbench.example`，普通部署不需要维护；只有明确需要调优时才在 `.env.workbench` 中增加覆盖项，并以 Compose 文件中的默认值为准。

Workbench Frontend 容器还会根据以下内部变量生成 Nginx 配置：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `SERVER_HOST` | `http://workbench:3000` | `/basilcraw/api/` 的 Workbench API 上游。 |
| `OBJECT_STORAGE_HOST` | `http://${MINIO_HOST}:${MINIO_PORT}` | `/bascilclaw` 对象文件代理的容器网络上游；不是 React 构建变量，也不是公网文件地址。 |
| `BASILOS_GATEWAY_HOST` | `CHANGE_ME_GATEWAY_URL` | `/basilos-subapp/`、`/oauth/`、`/basilos`、`/typekey` 的平台网关上游。 |

当前 Workbench Frontend 镜像使用 Docker DNS `127.0.0.11` 在请求时解析 `OBJECT_STORAGE_HOST`。MinIO 临时不可用时，仅对象文件路由应返回错误，前端 Nginx 本身仍应启动并在 MinIO 恢复后自动恢复代理。配置中的末尾 `/` 会由入口脚本规范化；`OBJECT_STORAGE_HOST` 必须填写容器可访问的内部地址，不要填写 `MINIO_PUBLIC_BASE_URL`。

## 配置检查

```bash
grep -n 'CHANGE_ME' .env.middleware .env.studio .env.workbench

docker compose --env-file .env.middleware config --quiet

docker compose \
  --env-file .env.middleware \
  --env-file .env.studio \
  -f docker-compose.studio.yaml \
  config --quiet

docker compose \
  --env-file .env.middleware \
  --env-file .env.workbench \
  -f docker-compose.workbench.yaml \
  config --quiet
```

`grep` 只允许命中未启用的可选配置。实际使用的地址、密码、密钥和镜像版本不能保留占位值。

### 新用户指令模板

Compose 固定配置 `USER_AGENT_INSTRUCTIONS_TEMPLATE_PATH=/app/storage/templates/AGENTS.md`。`workbench-storage-init` 校验 `workbench/storage/templates/AGENTS.md` 并设置权限，不复制或覆盖模板；创建新用户依赖该文件。部署包不再包含或播种内置 Library、多维表 App，也不要求配置其 OAuth 凭据。
