AOS Work Deployment Guide

Download English video (5 min 04 sec) Download English captions Download the installer

1. Prepare the server

Use a Linux host with at least 4 CPU cores, 8 GB of RAM, and 100 GB of total capacity on the file system that holds the deployment directory. The host needs access to GHCR and Docker Hub.

Point the Workbench, Studio, and self-hosted storage domains at the server. Allow inbound TCP ports 80 and 443 in both the cloud security group and the host firewall. You can skip the storage domain when using a cloud object store.

2. Upload and run the installer

Download deploy.sh above. For a first installation, create /home/aos-work in the Termius SFTP panel and upload the script there. For an existing installation, use its original directory. On the server, run this command for the directory shown in the guide.

sudo bash /home/aos-work/deploy.sh

Under Host preflight, check the CPU count, RAM, disk capacity, and free space. The installer also reports whether each port is free, in use by Nginx, or in conflict. Review any [WARN] messages. If dependencies are missing, enter y to install them.

3. Configure domains and deploy the services

  1. Select 1 in the main menu, then 1 for Workbench, 2 for Studio, or 3 for local storage. Enter the matching domain and wait for its HTTPS settings to be saved. The installer checks HTTP and HTTPS from the host using the domain’s DNS records.
  2. Enter 0 to return, then 2 to list the server packages. Select 1 for the first entry. The recording shows v2026.11.19. The installer linked here lists v2026.11.19.1 first.
  3. Select 3 in the main menu, then 3 again to deploy both Studio and Workbench. Choose local or external services for PostgreSQL, Redis, RabbitMQ, and object storage, and enter the requested credentials.
  4. After middleware setup, the installer deploys Studio and Workbench. Set the Studio data encryption password and the Workbench default password for new or reset users. For a single host, enter 0 for Stable sandbox host ID.
  5. When the checks pass, open the Studio and Workbench HTTPS addresses and confirm that both sign-in forms appear.

4. Check health and maintain services

Select 6 in the main menu. Long-running services should show running. Services with health checks should also show healthy. The one-time workbench-storage-init job shows exited after it finishes successfully. Look for All healthy in the summary.

Select 4 to update a service or 5 to restart one. Release notes and offline packages
