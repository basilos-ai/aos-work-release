# Base 业务背景

用于辨析业务对象和用户意图。明确的能力请求无需额外读取本文。 本文不定义 API 参数、执行顺序或授权；确定意图后使用 SKILL.md 中对应的能力契约，继续遵守原有初始化、确认、验证和交付流程。

## 对象与关系

| 对象 | 业务含义 |
| --- | --- |
| Base／库 | 组织数据表的容器，一个库可以包含多张表；不能与单张数据表混用。 |
| 数据表 | 通过字段定义数据结构，通过记录保存具体业务数据；业务含义来自实际名称、说明、字段和用户上下文。 |
| 字段 | 定义一种属性的名称、类型及配置；改变字段定义影响表结构，与填写记录值不同。 |
| 记录 | 一条结构化业务数据，由各字段的值组成；不能预设一定代表客户、合同或项目。 |
| 普通视图 | 同一张表上配置的筛选、排序、分组和展示方式；创建视图不等于复制记录或创建新表。 |

只有实际配置才能确定表和字段的业务含义。示例中的“客户”“状态”等不是默认业务模型；字段类型、可选值和标识从当前环境取得，不据名称猜测。

## 操作含义

- **新增／修改字段**：调整表结构或字段配置，使用 [fields.md](fields.md)。**填写／修改字段值**：调整目标记录的数据，使用 [records.md](records.md)。不能用字段定义变更代替记录更新。
- **筛选**：确定满足条件的记录；**排序**：安排展示顺序；**分组**：按字段组织记录。这些含义本身不授权修改原始记录，也不授权保存普通视图。记录查询的完整执行要求仍以 [record-query.md](record-query.md) 为准。
- **聚合**：对指定范围的数据进行统计，与返回逐条记录不同；使用 records.md 中的聚合契约，不从一页记录推算全量统计。
- **普通视图管理**：按 [views.md](views.md) 修改展示配置。删除普通视图与删除记录、字段、表或整个库是不同操作，不能互相替代。
- **删除业务对象**：先明确对象层级与目标范围，再使用相应契约。字段、表和库的删除影响不能按“只改展示”理解，也不推断未定义的级联或恢复行为。

查看、编辑、分享和发布是不同权限与操作范围。能看到数据不代表可以修改；不因用户请求查询或整理数据而擅自调整分享或发布配置。有效操作权限以服务端判定为准。

## 易混意图

| 用户表达 | 判别依据 |
| --- | --- |
| “把客户状态改为已联系” | 在已明确表和目标记录时属于记录值修改；不据此修改状态字段定义或批量修改整张表。 |
| “给客户表增加状态字段” | 属于字段定义创建；先核对实际表结构和所需类型，不把例子中的字段配置视为默认值。 |
| “按状态整理数据” | 区分临时查询／分组、保存普通视图与修改记录值；上下文不足时澄清实际目标。 |
| “删除这一列” | 区分从普通视图隐藏字段与删除字段定义；未明确时不能直接删除字段。 |

上下文已明确目标和操作时直接沿现有流程执行，不为这些例子增加固定澄清步骤。视图名称、表名称和记录内容都不能代替真实对象标识。
